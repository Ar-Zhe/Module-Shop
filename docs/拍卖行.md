# 拍卖行

拍卖行完全复用模块商店现有的星币钱包、邮箱、交易流水、存档、网络与配置，不另起一套货币或邮箱。

## 玩家怎么用

| 位置 | 功能 |
| --- | --- |
| 拍卖大厅（商店侧栏「拍卖会」） | 搜索、分类、排序、分页（滚轮翻页），每行显示物品 / 卖家 / 当前价或起拍价 / 最低下次出价 / 一口价 / 竞拍人数与次数 / 倒计时 / 领先者。左侧色条：橙 = 我的拍卖，绿 = 我领先，红 = 我被超过 |
| 详情页（点任意一行） | 完整物品属性、价格信息、出价（± 加价幅度）、一口价（点两次确认）、撤销（无人出价时）、竞价记录、管理员强制结束 / 撤销 |
| 上架（大厅右下角） | 直接从背包选物品（右键只选 1 个），设数量、起拍价、加价幅度、一口价、时长、是否允许竞价；下方实时显示上架费与成交手续费 |
| 我的拍卖 | 出售中 / 我的竞拍（是否仍领先）/ 已成交（成交价、买家、时间、手续费、到账）/ 已流拍 / 已撤销；历史记录可「重新上架」 |

**搜索**：输入后实时筛选，空格分隔多个关键词（每个都要命中），匹配物品显示名（当前语言）、物品 ID（如 `diamond_sword`，所以英文也能搜）、模组 ID 与模组名、附魔名、卖家名。清空即恢复完整列表。

**分类**：附魔书 → 药水 → 食物 → 武器 → 装备 → 工具 → 材料 → 方块 → 其他，按物品类型、NeoForge 通用标签（`c:tools`、`c:ingots`…）和数据组件判断，模组物品只要继承原版基类或带通用标签就能归对类，识别不了的进「其他」。

## 规则

* 最低出价 = 当前最高价 + 加价幅度；无人出价时为起拍价。加价幅度不低于配置 `auctionMinIncrement`，卖家可以设得更高。
* 出价立即扣款，钱由这场拍卖托管；被超过时**同一时刻**全额退回（余额装不下的部分转金额邮件）。
* 不能给自己的拍卖出价；已经领先时不能再出价；出价达到一口价时提示直接用一口价。
* 一口价：服务端检查拍卖仍有效 → 检查余额 → 扣款（自己领先时已托管的出价抵扣）→ 退还原领先者 → 物品邮件给买家 → 货款邮件给卖家 → 记流水 → 结束拍卖，全部在一次调用内完成。两人同时一口价时，后到的那位会收到「已售出」。
* 防截拍：剩余时间少于 `antiSnipeSeconds` 时出价，延长 `antiSnipeExtensionSeconds` 秒；最多 `antiSnipeMaxExtensions` 次，并且总时长封顶为原时长的 2 倍。
* 撤销：无人出价时卖家可撤销（物品回背包，放不下进邮箱）；有人出价后不能撤销；管理员可强制撤销（出价全额退还、物品邮件退回卖家）。上架费不退。
* 重新上架只带出价格与时长；物品必须从背包重新选择，服务端按槽位核对实物，**不能凭历史记录复制物品**。

## 配置（`config/module_shop-common.toml` 的 `[auction]`）

管理员也可以在大厅右上角「管理」里改，保存即写回配置文件，重启后仍生效。

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `auctionEnabled` | `true` | 关闭后不能上架 / 出价 / 一口价；已有拍卖照常到期结算 |
| `maxAuctionsGlobal` | `500` | 全服同时进行的拍卖上限 |
| `maxConcurrentAuctions` | `6` | 每人同时进行的拍卖上限（旧键） |
| `auctionDurationOptions` | `30,60,180,360,720,1440,2880` | 可选时长（分钟），第一个为默认 |
| `auctionDurationSeconds` | `7200` | 旧版「存放槽」上架流程使用的时长（旧键） |
| `auctionMinIncrement` | `10` | 最低加价幅度（旧键） |
| `auctionListingFeeFixed` / `auctionListingFeePercent` | `0` / `0.0` | 上架费 = 固定 + 起拍价 × 百分比；余额不足禁止上架，上架失败不扣费 |
| `auctionFeePercent` | `5.0` | 成交手续费（从卖家所得扣除，旧键） |
| `auctionMinStartPrice` / `auctionMaxStartPrice` | `1` / `0` | 起拍价范围（0 = 只受余额上限约束） |
| `auctionAllowBuyout` | `true` | 是否允许一口价 |
| `auctionMaxItemCount` | `64` | 单场最多几件（不超过该物品堆叠上限） |
| `antiSnipe` / `antiSnipeSeconds` / `antiSnipeExtensionSeconds` / `antiSnipeMaxExtensions` | `true` / `60` / `30` / `10` | 防截拍（前三个是旧键；旧配置里延长秒数是 0，需要手动改成非 0 才会生效） |
| `auctionBlacklist` | 基岩、屏障、命令方块、刷怪笼等 | 物品 ID、`#标签`、`模组ID:*`；**潜影盒 / 收纳袋里的物品同样检查** |
| `auctionAllowBound` / `auctionBoundMarkers` | `false` / `Soulbound…` | 绑定物品（绑定诅咒，或 custom_data 顶层含这些键）是否可拍卖 |
| `auctionAllowCustomData` | `true` | 是否允许带 custom_data（特殊 NBT）的物品 |
| `auctionMaxItemNbtBytes` | `32768` | 物品序列化后的体积上限（防超大 NBT 拖垮网络与存档） |
| `auctionBlockCreative` | `true` | 创造模式不能上架（创造模式可以凭空生成物品） |
| `auctionEndingSoonSeconds` | `300` | 剩余这么多秒时提醒卖家与领先者 |
| `auctionHistoryLimit` | `2000` | 保留多少条已结束记录（损坏 / 有托管余额的记录不会被自动清理） |

## 管理命令（2 级权限）

```text
/shop auction                 打开拍卖大厅
/shop auction list            进行中的拍卖（含托管金额、剩余时间）
/shop auction history [页]     已结束的拍卖记录（异常记录标红）
/shop auction anomalies       资金 / 结算异常日志
/shop auction audit           立即做一次资金托管审计
/shop auction cancel <id>     强制撤销（出价全额退还，物品邮件退回卖家）
/shop auction end <id>        强制结束（按当前状态立刻结算）
```

## 资产安全设计

* **服务端权威**：成交价、余额、最低出价、拍卖结束、竞拍成功、物品交付、退款金额全部由服务端决定。客户端只发「我要出多少」以及「我看到的当前价」（`expect`），服务端发现价格已变就拒绝并推送最新数据。
* **一把锁 + 主线程**：所有拍卖操作都在服务端主线程、`ShopManager.LOCK` 内执行，多人同时竞价按到达顺序处理。
* **原子性**：余额、托管、物品、邮件都存放在同一份 `ShopSavedData`，物品交付一律走邮箱。存档在 tick 边界整体写盘，磁盘上只会出现操作前或操作后的完整状态。
* **资金托管**：`AuctionEntry.escrow` 记录托管额。不变式：进行中 `escrow == (有出价 ? 当前价 : 0)`，已结束 `escrow == 0`。服务器启动时自动审计一次，`/shop auction audit` 可随时审计，不一致写入异常日志（不自动改账，交给管理员判断）。
* **幂等**：每个提交带随机请求号，同一请求号只处理一次（网络重发 / 连点）。结算第一步就把拍卖移出进行中列表，已结算的不会再被处理。
* **重启恢复**：进行中的拍卖、托管资金都在存档里；到期但没来得及结算的拍卖，重启后第一次 tick 就会结算。
* **上架不再「悬空」**：新上架界面在一次调用里完成校验 → 扣费 → 取物品 → 建拍卖，物品不会暂存在内存里。旧的「存放槽 → 输入起拍价」流程仍保留给 AtomLib 不可用的客户端，并走同一套规则。
* **离线玩家**：退款先进余额，装不下转金额邮件；物品与货款都走邮箱，下线也能收到。
* **邮箱已满**：现在会**超额保存**，不再丢失物品。以前离线时物品会凭空消失，在线时会掉在地上。这一条修复对所有模块都生效。
* **金额**：负数、非数字、超过余额上限一律拒绝；加法饱和不溢出；手续费不会超过成交价。
* **损坏数据**：物品解析失败（例如模组被移除）时原始数据原样保留、照常写回存档；到期时退还出价并标为「物品损坏」，记录不会被自动清理。整条拍卖读不出来时隔离到 `auctionCorrupt`，存档其余部分照常读取。
* **隐私**：竞价记录只下发名字、金额、距今多久，不下发 UUID。

## 网络与性能

* 拍卖列表不再随每次商店快照全量下发：打开拍卖页时拉一次（带版本号，没变化只回「未变化」），之后只收增量（本 tick 变化的条目合并成一个包，只发给打开过大厅的在线玩家）。
* 拍品编码只做一次并缓存（拍品上架后不变）。
* 搜索 / 分类 / 排序都在客户端完成：服务端不知道玩家用什么语言，没法按中文名搜索。列表规模由 `maxAuctionsGlobal` 封顶。
* 到期扫描每 10 tick 一次。

## 存档兼容

`AuctionEntry` 原有字段名和含义都不变；新增字段缺失时取安全默认值：状态 = 进行中，托管 = 当前价（旧版同样是出价即扣款），创建时间按「结束时间 − 当前配置时长」推算，旧的最高出价者计入竞拍者并补一条出价记录。旧存档里的 `auctions` 列表照常读取；新增的 `auctionHistory` / `auctionAnomalies` / `auctionCorrupt` 在旧存档里为空。

## 已知限制

* 新界面（大厅搜索 / 分类、详情、上架、我的拍卖、管理）只在 AtomLib 可用时显示。AtomLib 不可用时（非 Windows）退回旧大厅、旧出价框、旧的存放槽上架流程，出价 / 结算规则相同，但没有一口价按钮和「我的拍卖」。
* 拍卖邮件正文沿用项目现有的中文模板（邮件模板本来就不分语言）。
* 资金异常只记录、不自动修复，需要管理员根据异常日志处理。
