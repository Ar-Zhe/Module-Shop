# 第六轮（第四批）需求实现说明

本批四件事：**签到界面重做 + 日程系统**、**统一暗色与按钮对齐**、**上架流程返回修复**、**滚动提示**。

## 一、签到界面重做与日程系统（需求 ①）

* **里程进度条**：改成细长一条（高 5px）；里程点是**小圆**，达到连续天数即**点亮**（绿色实心 + 外圈淡光），圆下两行小字显示「N d」与该档里程奖励金额。左上角原来那行「连续签到」文字已删除，连续天数靠进度条与圆点体现；每日可得金额放在标题行右侧。
* **日历**：**年份在左、月份在右**，各自的翻页按钮（`<< >>` 与 `< >`）就放在各自那一侧；月份名与星期表头按客户端语言自动本地化。
* **布局**：标题 → 细进度条 + 圆点 → 签到按钮 → 日历表头 → 周表头 → 日期格（6 行）→ 管理员按钮行，各段互不重叠（面板 380×268）。
* **「签到设置」改名为「连续签到设置」**（中英同步）。
* **编辑模式**：不再点进度条高亮，改为点「编辑」按钮进入**日程编辑模式**；编辑态下**点任意日期即新建日程**；非编辑态点过去的日期仍是补签。
* **日程标记**：日期格**底部一条颜色小条**（一天最多 3 条横向平分，不压日期数字）；**鼠标悬浮**该日期弹出悬浮窗，按行显示该日全部日程的**名称 + 正文（+ 金额）**。
* **独立日程编辑界面** `ScheduleEditScreen`（iOS 风格面板，不再用输入弹窗）：**颜色色板点选**（10 个预设色 + 选中描边）、**名称**、**正文**、**定时小时**（现实时间 0-23，留空=不定时）、**星币金额**、**物品**（`minecraft:diamond x2`）、**允许离线领取**开关，以及**保存 / 取消 / 删除日程**按钮。
* **定时发放**：服务端 `tickActivitySchedules` 每分钟检查，到达日程设定的**现实时间点**时给**当时在线**的玩家发放星币与物品；开启**允许离线领取**的玩家在**当天首次登录**时补发；物品（含额外物品）统一走**邮箱**领取；全部记入交易流水（`sign_in` 类型）。发放去重记录持久化在存档里。
* **数据**：`ActivityDay` 扩展 `color` / `hour` / `gift` / `giftGranted`，老存档缺字段自动用默认值；原有「活动日」数据即为日程，无需迁移。

## 二、统一暗色与按钮对齐（需求 ②）

* **删除顶部栏的太阳/月亮主题切换按钮**，`UITheme.ensureLoaded()` 固定为暗色（忽略客户端历史保存的浅色主题），所有界面统一暗色。
* **「签到」按钮移到「交易」左边并与之一一对齐**：与交易/转账同尺寸（52×18）、同一 y、8px 等距。

## 三、上架流程返回修复（需求 ③）

* 原因一：服务端打开的界面（数量输入弹窗、摊位浏览、交易、交易请求）直接用 `minecraft.setScreen(...)`，没有记录「上一级」。
* 原因二：放物品的容器界面（`DepositScreen`）由原版菜单打开，关闭时 `Nav.back()` 弹到的是过期状态 → 于是跳到每日商店或全部关掉。
* 修法：这些界面统一改走 `Nav.open(...)`；`DepositScreen` 关闭改为新增的 **`Nav.backToShop()`**（优先返回返回栈里的商店界面，栈里没有就按上次页签新建）；交易关闭时清空返回栈。现在「摊位 → 上架物品」「拍卖 → 拍卖上架」无论取消还是确认，都会**回到摊位/拍卖页**。

## 四、滚动提示（需求 ④）

* 面板底部居中显示一个**朝下的小三角**，用 `sin(tick/6)` 做上下约 2px 的**缓慢浮动**。
* 触发条件：当前列表**还有内容未显示完**时置位，帧末统一绘制。已接入：每日商店长条模式、每日收购、货币兑换、商店设置列表。
