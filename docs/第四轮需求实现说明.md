# 第四轮需求实现说明（v1.13.0）

本轮三件事：**币种统一为「星币」**、**界面调整（新增货币兑换页签 + 管理员入口右下角化 + 商店设置页排版重做）**、
**新增货币兑换模块（物品 ⇄ 星币双向兑换 + 日间/暗色主题）**。

## 1. 币种统一为「星币」（含英文翻译）

| 位置 | 改动 |
| --- | --- |
| 服务端配置 | `[wallet] currencyName` 默认值 → `"星币"`，随每次快照下发 |
| 中文语言文件 | 39 处「金币 / 金钱」→「星币」；`msg.server_shop_mod.balance` → `余额：%s 星币` |
| 英文语言文件 | `gold coins / gold / coins` → `Star Coins`；`balance` → `Balance: %s Star Coins` |
| 客户端显示 | 新增语言键 `currency.server_shop_mod.default`（中「星币」/ 英 `Star Coin`）：货币名等于默认值时走语言文件，**英文客户端自动显示 `1000 Star Coin`** |
| 自定义货币名 | 服主在配置里改成别的名字时原样显示（ASCII 名自动补空格，中文名紧跟数字） |
| 文档 | README / DESCRIPTION / MCMod 正文 / 各轮说明全部统一为「星币」 |

实现要点：`ClientShopData.money(long)` 不再硬编码货币名，改为 `currencyName()`：

```java
public static String money(long amount) {
    String name = currencyName();          // 默认值 → 语言文件翻译，自定义值 → 原样
    return amount + (name.charAt(0) < 0x80 ? " " : "") + name;
}
```

> 兼容性：老配置/老存档不需要任何改动，只是显示旧货币名；把配置里的 `currencyName` 改成 `星币`
> （或删掉该项用新默认值）即可获得中英双语效果。

## 2. 界面调整

### 2.1 侧栏新增「货币兑换」页签（在「邮箱」下面）

* `TAB_IDS = {daily, buyback, auction, stall, mail, exchange}`，快捷键 `1`~`6` 依次打开；
* 该页签对所有玩家可见（兑换是玩家功能），不在侧栏显示红点。

### 2.2 管理员入口移到右下角

* 侧栏不再出现「商店设置」页签；
* 界面**右下角**新增小按钮「商店设置」（56 × 13，文字缩到 0.8 倍），完全落在面板内部、不超出边框；
* 为了让这个按钮不与任何模块的右下角控件（每日商店的刷新、拍卖的上架、邮箱的翻页…）打架，
  主界面给底部留出了一条 **18px 的专属条带**（内容区高度相应减 18px），按钮就放在这条带里；
* 只有 2 级权限玩家才绘制与响应（`canAdmin` 由服务端下发），点击即切换到商店设置页；
* 服务端对任何 `admin_*` 操作仍会再校验一次权限，客户端按钮只是显示层的开关。

### 2.3 商店设置（管理员）页排版重做

原来的按钮大小不一、互相遮挡（发放入口盖住翻页键）。现在统一为：

```
┌ 顶部：[每日商店][每日收购]      当前编辑：每日商店
│ 条目列表（5 行/页，行高 22）
│
│ [添加条目][发放物品][交易记录]          ← 第一行：三枚等宽小按钮（78×14）
└ [上一页][下一页] 第 1/3 页     左键编辑…右键删除  ← 第二行：翻页 + 提示（0.8 倍字号右对齐）
```

* 所有按钮统一 14 高、文字 0.8 倍、间距固定 4px，翻页键与提示分属两行，**不再有任何重叠**；
* 条目列表因为底部让出了按钮条带，每页从 6 条改为 **5 条**（滚轮翻页逻辑同步改为 5 条/页）；
* 模块按钮用蓝色高亮当前编辑对象（而不是「选中/未选中」两套配色），一眼看清在改哪个池子。

## 3. 货币兑换模块

### 3.1 玩家视角

* 每种货币一条**长方形条目**，行内显示「物品图标 + 名称 + `= N星币`」，收起时右侧有 `v` 展开标记；
* **左键点击展开**（同时只展开一行），展开后显示「背包持有数量」「最多可取出数量」以及按钮：
  * **兑换**（物品 → 星币）
  * **取款**（星币 → 物品）
* **滚轮**上下浏览；条目多于一屏时右侧出现金色滚动条（像素级滚动，兼容展开行高度变化）；
* 兑换弹数量输入框，默认填满背包持有量，可改小；按「数量 × 汇率」入账；
  **余额快满时只收还能装下的部分，剩下的物品原样留在背包**，绝不吞物品；
* 取款弹数量输入框，默认 1 个并显示当前余额；按「数量 × 汇率」扣款后把货币发到背包，**背包放不下自动进邮箱**；
* 两种操作都会写进交易流水（`货币兑换` / `货币取款`），管理员 `/shop admin history <玩家>` 可查。

### 3.2 管理员视角

* 兑换页右下角「添加货币」→ 打开**幽灵槽**界面放入货币物品（原物退回背包，不会被消耗）→ 输入「1 个 = 多少星币」；
* 展开任意一行 → **改价**（带出当前汇率）/ **删除**；
* 同一物品重复添加自动视为改价，列表不会出现重复条目；
* 汇率必须是 `> 0` 且 `≤ maxBalance`（防止 `汇率 × 数量` 溢出成负数导致刷钱）；
* 模板物品只作展示与匹配，**删除条目不退还模板**（与每日商店商品池一致，避免复制物品）。

### 3.3 数据结构与存档

* **老存档没有该标签时按空列表处理**（已实机验证：旧存档启动无异常，关闭后数据文件里出现 `exchangePool`）。

## 5. 安全性与数值一致性

* 兑换与取款都在 `ShopManager.LOCK` 内结算，避免多玩家同时兑换导致余额错乱；
* 所有入账走 `credit()`（饱和加法，永不溢出、不变负）；所有乘法走 `safeMultiply()`；汇率解析走 `parsePrice()`；
* 兑换按 `takeMatching()` 的**实际取走数量**结算，绝不按客户端请求数量扣；
* 取款先确认 `余额 ≥ 数量 × 汇率`，扣款后统一用 `deliver()` 发货（背包 → 邮箱）；
* 所有 `admin_exchange_*` 在服务端入口统一做 `hasPermissions(2)` 校验。

## 7. 部署注意（重要）

* 配置文件必须是**不带 BOM 的 UTF-8**。带 BOM 时 NeoForge 会报
  `Failed to load config ... ParsingException: Invalid bare key: '\ufeff[wallet'` 并**把配置重置为默认值**
  （本轮服务器就遇到了这个情况，已修复并恢复自定义项）。
  用记事本「另存为 → UTF-8」可能写入 BOM，建议用 VS Code 等工具确认编码为 `UTF-8`（非 `UTF-8 with BOM`）。
* 版本号保持 `1.13.0`（jar 文件名不变，避免同 modId 重复加载报错）；替换 `mods/` 里的 jar 后重启即可。
* 客户端与服务端**必须是同一个 jar**（界面是客户端代码）。
