# 玩家商店（摊位）

在原有「玩家摊位」系统上升级。原来的摊位数据、「逛摊位」入口、存放槽上架、改价、下架、限时下架全部保留。新增的部分直接复用原有的摊位数据和交易逻辑，没有另建一套商品库。

侧栏「摊位」页顶部有三个入口：

| 入口 | 内容 |
| --- | --- |
| **我的商店**（默认，原「我的摊位」） | 两列格子管理自己的商品：点格子改价，「+」补货，「×」下架；底部「上架商品」（从背包选择）、「交易记录」（只看摊位买卖）、在售数量与累计售出 |
| **商店大厅**（新） | 汇总所有玩家摊位上**有货**的商品：搜索（名称 / 物品 ID / 卖家）、分类、按最新 / 价格排序、分页（滚轮翻页）。点商品直接进入卖家的摊位，并预选这件商品 |
| **查看摊位**（原有） | 打开有摊位的玩家列表，点玩家进入他的摊位 |

## 摊位详情（查看摊位 / 从大厅进入）

* 顶部：「某某 的商店」、店主、营业状态（有货 = 营业中）、商品种数与有货种数。原系统没有摊位编号，所以这里不显示编号。
* 左侧：物品格子卡片（图标、名称、单价、库存 / 售罄），选中有高亮，商品多时分页（滚轮或翻页按钮）。
* 右侧：选中商品的单价、库存、已售；购买数量（− / 输入 / + / 最大，限制在 1 ~ 库存）；**总价 = 单价 × 数量**实时计算；显示余额，余额不足或数量不合法时购买按钮不可点并给出原因。
* 购买成功后，界面就地刷新库存，不会关闭重开。

## 交易安全

* **按商品 id 购买**：原来按「第几件」定位商品，卖家在你浏览时下架其它商品，下标就会错位，可能买成另一件商品、付另一个价格。现在每件商品有全服唯一的 id（即原有的 `order` 上架序号），购买、改价、补货、下架都按 id 定位，旧客户端只带下标时仍兼容。
* **价格核对**：购买时附带「我看到的单价」，卖家刚改过价就拒绝并刷新，不会按没看到的价格扣款。
* **数量**：超过库存直接拒绝（原来是悄悄按库存数量少卖），服务端校验 1 ~ 库存。
* **重复点击 / 网络重发**：每次购买、上架、补货都带随机请求号，同一请求只处理一次；界面上提交后也会锁定按钮，直到服务端回包。
* **并发**：购买、改价、补货、下架都在 `ShopManager.LOCK` 内、服务端主线程执行，库存不会被扣成负数。
* **上架必须真的有物品**：新上架界面只发「槽位 + 物品 + 数量 + 单价」，服务端核对那一格里确实有这么多，再在同一次调用里收上架费、取物品、入库。
* **补货只收完全相同的物品**：物品、附魔、耐久、自定义数据都要一致。原有的 `takeMatching` 只比较物品种类，补货改用新的比较方法。
* **下架**：先从摊位移除，再把剩余库存全部退回（背包放不下的进邮箱），不丢不复制。
* **卖家离线**：货款直接进卖家钱包（余额上限装不下的部分转金额邮件），与原逻辑一致。
* **持久化**：商品、库存、累计售出都在原有的 `ShopSavedData` 里，重启后照常恢复；交易记录沿用原有交易流水。

## 配置

`[stall]` 段新增 `stallMaxStock`（默认 64）：单件商品的库存上限，上架和补货共用。原来这个值写死为 64。其余沿用原有配置：`stallSlots`、`stallListingFeePercent`，以及摊位下架时间。

## 顺带修复

* 摊位交易流水的备注原来是 `translation{key='item.minecraft.diamond'…}×3` 这种乱码，现在显示物品名。
* 卖家流水的备注写着「货款存邮箱」，实际货款早已改为直接进钱包，备注已更正。
