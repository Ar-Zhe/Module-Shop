# 第七轮设计方案：邮箱系统（鸣潮风格）＋ 邮件模板体系 ＋ 兑换码系统

> 技术栈按**本项目实际情况**：Minecraft **1.21.1 / NeoForge 21.1.x**（Arclight 混合端实测），纯 Java 21，
> 服务端权威 + 自定义客户端 Screen（无 Vue/后端服务）。货币名统一 **星币**，玩家称呼统一 **玩家名/UUID**。

---

## 〇、现状盘点（必须并入、不能丢的旧邮箱能力）

| 现有能力 | 位置 | 说明 |
| --- | --- | --- |
| 邮件实体 | `data/MailEntry.java` | `mailId`、`type`(ITEM/MONEY)、`stack`、`source`、`sender`、`senderUUID`、`currencyAmount`、`isClaimed`、`isViewed`、`sentAt`、`receivedDay` |
| 发件入口 | `ShopManager.addMail / addMoneyMail / addItemOrMail / deliver` | 物品进邮箱、金额进邮箱、背包放不下自动转邮箱 |
| 领取/查看 | `ShopManager.claimMail / viewMail / claimAllMail / deleteMail / deleteReadMail` | 服务端按 `mailId` 查表，**绝不信任客户端下标** |
| 来源常量 | `SOURCE_AUCTION_UNSOLD/WON/SOLD/REFUND`、`SOURCE_STALL_UNSOLD/SOLD/BOUGHT`、`SOURCE_ADMIN`、`SOURCE_EXCHANGE` | 决定邮件说明文案与图标 |
| 上限与翻页 | `Config.maxMailboxSize`（默认 100）、界面每页 45 封 | 邮箱满：物品改为直接掉落/金额直接到账并提示 |
| 过期清理 | `Config.mailExpireDays`（0=永久；>0 只清理已领取/已查看） | 挂在每日维护 tick |
| 未读红点 | `NotificationManager` + `MailType` | 页签红点、聊天提醒 |
| 物品保护 | `ShopNbt.deepCopy`（跨信任边界深拷贝）、`ItemStack.parseOptional` 落盘 | 容器类物品不串号 |
| 流水 | `TransactionLog`（`MAIL_ITEM` / `MAIL_MONEY` …） | 领取/查看到账都记流水 |
| 管理发放 | `GrantManager`（幽灵槽 + 玩家多选 + 金额） | 物品进邮箱、金额直接到账 |
| 活动日/日程 | `ActivityDay` + `tickActivitySchedules` | 定时发物品/星币 → 邮箱 |

**本方案的硬约束**：以上每一个入口/出口都要继续可用，新模式只是**在既有 `MailEntry` 上扩展字段**并把 UI 换成鸣潮式左右分栏。

## 一、UI/UX 设计（对齐《鸣潮》邮箱）

### 1.1 主界面：左右分栏
```
┌───────────────────────── 邮箱 ───────────────────────── [兑换码] ┐
│ ┌── 全部邮件  13/99 ──┐ │  【标题】版本更新补偿          ★ 未读  │
│ │ ● 《服务器》项目组   │ │  发件人：服务器管理组                │
│ │   版本更新补偿   2天前│ │  时间：2026-09-28 20:15              │
│ │ ──────────────────  │ │ ─────────────────────────────────── │
│ │ ○ 拍卖会系统         │ │  正文（支持 & 颜色代码与换行）        │
│ │   您的物品已售出 1天前│ │                                      │
│ │ ──────────────────  │ │ ┌ 附件 ───────────────────────────┐ │
│ │ ★ 摊位系统           │ │ │ [图标] 钻石 ×2   [图标] 星币 ×1000│ │
│ │   商品售出通知   3天前│ │ └────────────────────────────────┘ │
│ └─────────────────────┘ │                        [ 领取 ]      │
├─────────────────────────┴──────────────────────────────────────┤
│ [全部领取]  [删除已读]                    剩余 86 封 · 第 1/2 页 │
└────────────────────────────────────────────────────────────────┘
```
* 左栏：顶部「全部邮件 + 容量 13/99」，每行 = 状态点（未读●/已读○/星标★）+ 发件人 + 标题 + 相对时间；滚轮整行滚动 + 底部浮动提示（沿用第 ④ 条）。
* 右栏：标题（带颜色/图标）、发件人、绝对时间、正文、附件格子（物品图标 + 数量；金额用星币图标 + 数字）；右下角「领取」按钮（已领取时变为灰色「已领取」）；右上角星标可点切换。
* 底栏：左「全部领取」「删除已读」，右容量与页码；沿用 `Nav` 返回栈与 iOS 暗色风格（`IOStyle`），**全部暗色，无浅色主题**。
* 现有 9×5=45 封网格改为列表后，每页仍 45 行（滚轮滚动 + 页码），容量上限仍读 `maxMailboxSize`。

### 1.2 状态机（与旧字段一一对应）
| 状态 | 字段 | UI 表现 |
| --- | --- | --- |
| 未读 | `isViewed=false`（金额）/ `isClaimed=false`（物品） | 左侧实心圆点 + 标题加粗 + 页签红点 |
| 已读 | `isViewed=true` / — | 空心圆点 |
| 附件待领取 | `pending()` | 附件格子高亮 + 「领取」按钮可点 |
| 附件已领取 | `isClaimed=true` / `isViewed=true` | 附件格子灰化（`DONE_WASH`）+ 「已领取」 |
| 星标 | **新增** `starred` | 左上角金色★，置顶排序可选 |
| 已过期 | **新增** `expireAt`（0=永久） | 「15 天后自动删除」倒计时；到期由每日维护清理 |

### 1.3 邮件类型（图标/配色）
`MailType` 扩展为带 `id + icon + color + template`：`SYSTEM`(系统/补偿/公告, 金)、`AUCTION`(拍卖, 紫)、`STALL`(摊位, 蓝)、`TRADE`(交易, 青)、`REDEEM`(兑换码, 橙)、`ACTIVITY`(活动, 绿)、`REFUND`(退回, 灰)。旧 `item/money` 作为「附件形态」保留，不作为类型，避免破坏存档兼容。

### 1.4 背包拦截（核心交互）
点「领取」/「全部领取」时服务端先算**所需槽位**：
1. 把所有待领物品按 `(item, components)` 合并；
2. 优先填入背包现有同类未满堆叠，余量按 `maxStackSize` 折算新槽位；
3. `需求槽位 > 空槽位` → **阻止领取**，聊天与界面同时提示 `背包物品已达限额提醒`（红色），并在详情区高亮需要腾出的格数；
4. 「全部领取」= 所有待领附件的合并计算，空间不足时**整批不发**（不做部分领取，避免玩家困惑），并提示缺少几格。
（金额类附件不占槽位，可单独领取：空间不足时只发金额、物品留在邮箱。）

### 1.5 邮件生命周期
| 类型 | 默认有效期 |
| --- | --- |
| 拍卖 / 摊售 / 交易 / 退款（资产类） | **30 天** |
| 兑换码奖励 | **15 天** |
| 系统公告 / 补偿 / 活动全服奖励 | **永久**（`expireAt=0`） |
到期由每日维护删除**未领取也删**（资产类会先在到期前 24h 发一封提醒邮件，可配置）；`Config.mailExpireDays` 保留为「兜底全局天数」，优先级低于单封 `expireAt`。

## 二、邮件模板体系（15 个标准模板）

实现见 `src/main/java/cn/autoforged/server_shop_mod_1789689358/shop/mail/MailTemplates.java`：

* `MailTemplates.Template` 枚举：`AUCTION_WON / AUCTION_OUTBID / AUCTION_UNSOLD / AUCTION_SOLD / AUCTION_UNLISTED / STALL_SOLD / STALL_EXPIRED / STALL_BOUGHT / TRADE_DONE / TRADE_CANCELLED / TRADE_DENIED / REDEEM_OK / BAG_FULL / SYSTEM_NOTICE / ACTIVITY_REWARD`，每个带 `type / sender / title / content / defaultExpireDays / hasAttachment`。
* `MailTemplates.resolve(text, map)`（占位符解析器）：`{player} {target} {item} {amount} {price} {fee} {income} {newPrice} {buyer} {code} {activityName} {time}`；重复占位符一次替换，未知占位符保留原样（便于排查）。
* `MailTemplates.build(template, placeholders)` → `DraftMail`：`title/content/sender/type/expireAt/attachments`，并支持 `&e &a &c &7` 颜色代码与 `\n` 换行。
* `DraftMail.toItemTag()/toMoneyTag()`：转成**现有 `MailEntry` 能直接吃的标签**，因此只需在 `ShopManager.addMail/addMoneyMail` 增加 3 个字段（`title/content/expireAt`）即可全量迁移，旧调用点零改动。

> 颜色约定：`&e` 金色=奖励/成功通知、`&a` 绿色=交易/售出、`&c` 红色=失败/拦截、`&7` 灰色=退回/下架。

## 三、兑换码系统

### 3.1 数据（服务端权威，存 `ShopSavedData`）
```java
class RedeemCode {
    String code;              // 统一大写、去空格（WUWA-8X9K-2M4P 形式）
    long expireAt;            // 0 = 永久
    boolean global;           // true=全服通用；false=指定玩家
    Set<UUID> players;        // 指定玩家白名单
    int perPlayerLimit;       // 每人可用次数（默认 1，0 = 不限）
    int totalLimit;           // 总使用上限（0 = 不限）
    int usedCount;
    Map<UUID,Integer> usedBy; // 每人已用次数
    List<ItemStack> items;    // 物品奖励（深拷贝落盘）
    long money;               // 星币奖励
    String title, note;       // 邮件标题/备注
    String creator;           // 生成者
}
```
### 3.2 交互流程（玩家）
1. 邮箱界面**右上角「兑换码」按钮**（礼物盒图标，`IOStyle` 图标按钮）。
2. 点击 → **半透明深色 Modal**：标题「兑换码」、单个输入框（提示「请输入兑换码」）、`[确认] [取消]`。
3. 细节：输入框**自动聚焦**、支持 `Ctrl+V`；输入自动 **转大写 + 去首尾空格**；点确认后按钮置灰显示「兑换中...」防连点；**回车键**=确认；`ESC`=取消（走 `Nav` 返回栈）。
4. 失败（不存在/过期/已用完/不属于该玩家/背包与邮箱都满）：输入框**变红并抖动 ~0.4s**，下方红字说明原因；成功后弹窗关闭，屏幕中央弹**奖励展示**（物品图标 + 金额），奖励**发到邮箱**并自动跳转到该邮件。

### 3.3 兑换码生成器（管理员，藏在兑换码界面的空白处）
* 入口：兑换码 Modal 左下角极小的「生成器」热区（仅 `canAdmin` 绘制与响应，服务端对 `admin_redeem_*` 二次校验）。
* 界面：标题栏「兑换码生成器」+ 右上角关闭；**基础配置**：兑换码输入框 + 🎲 随机生成（`WUWA-8X9K-2M4P`）、时效快捷 `[7天][30天][永久]` + 自定义日期时间、领取范围（全服 / 指定玩家 → 玩家搜索 + 列表多选）、数量设置（每人限领、总上限）；**奖励配置**：物品列表（「添加物品」→ 物品搜索/创造栏式选择 → 图标+名称+数量 ± ）、金额输入（±）、标题与备注；**底部**：左「清空重置」、右主按钮「生成兑换码」。
* 防呆：必填为空 → 生成按钮置灰；重复兑换码 → 输入框变红「该兑换码已存在」；点生成 → 确认框「确认生成？全服通用，限领 1 次，包含 2 个钻石 和 1000 星币」→ 生成后**复制到剪贴板**并提示「生成成功」。

## 四、通信与落盘（沿用本项目现有机制）

* **下发**：`ClientboundShopSyncPayload` 的 snapshot 增加 `mailV2`（每封：标题/正文/发件人/时间/`expireAt`/`starred`/状态/附件物品与金额/类型图标）+ `redeemCodes`（仅管理员）。
* **上行**：`ServerboundShopActionPayload` 新增动作（全部走服务端校验）：
  `mail_claim`（已有 `claim_mail`）、`mail_claim_all_v2`、`mail_delete_read`（已有）、`mail_star`、`redeem_code`、`admin_redeem_create`、`admin_redeem_delete`。
* **兼容**：旧 `MailEntry` 存读档字段全部保留，新字段缺省时按旧行为（永久、非星标、无标题 → 用 `source` 生成默认标题）。
* **物品保护**：奖励入邮箱前统一 `ShopNbt.deepCopy`；领取时先算槽位再发货，**先扣邮件后发货**的顺序改为**先验证可放入 → 再标记已领 → 最后放入**，任何一步失败都不消费邮件。
* **流水**：兑换码领取记 `TransactionLog` 新类型 `REDEEM`；批量领取沿用 `MAIL_ITEM` / `MAIL_MONEY`。
