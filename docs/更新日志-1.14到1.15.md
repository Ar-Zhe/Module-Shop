## 一、中文更新日志

### 1. 修复：商店数据太大导致玩家掉线（重要）

* **现象**：玩家一打开商店就被踢下线，客户端生成 `disconnect-…-client.txt`，里面写着
  `Failed to decode packet 'clientbound/minecraft:custom_payload'` +
  `Tried to read NBT tag that was too big; tried to allocate: 2097118 + 36 bytes where max allowed: 2097152`。
* **原因**：原版单个 NBT **超过 2 MiB 就直接抛异常**。购物城整包导入（最多 2000 件）之后，商店快照超了 2 MiB，
  于是**每个开商店的玩家都会被踢**；客户端→服务端的「整包导入模组」也走同一条路，同样会崩。
* **修法**：同步数据改成 **先 gzip 压缩、再按 512 KiB 分片**传输，接收端集齐后解压（解压上限 64 MiB，不再经过原版的 2 MiB 限制）。
  两个方向都改了，所以导入模组也不会再掉线；顺带**更省流量**（商店数据里重复物品 id 极多）。
* **更稳**：分包超时 / 超量 / 解压失败**只记一条日志并丢弃这一包**，这次操作不生效而已，不会再变成「Network Protocol Error」掉线。
* **快照瘦身**：管理端专用列表（商店 / 收购 / 购物城的管理列表）只发给管理员，普通玩家的同步体积直接砍掉一大截。

### 2. 新增：购物城「定时补货」

* 位置：**商店设置 → 模块选购物城 → 「补货设置」**。
* 四步填完就好（开关和口径都是按钮，点一下就选中）：
  * **定时补货 关 / 开**；
  * **时间口径：现实时间 / 游戏时间**（现实 = 和「每日额度重置」同一套分界；游戏 = 和出货箱结算一致，06:00 = 游戏 0 刻）；
  * **补货时刻**（HH:mm，只填数字会自动补冒号 `0600` → `06:00`；格式不对红字提示并且拒绝保存）；
  * **补货数量**：`0` = 每件补回**各自原量**；`>0` = 所有商品**统一补到该数量**。
* 每件商品会记住**补货目标**（你上架 / 编辑 / 导入时填的库存数），卖到 0 之后到点补回这个数；
  **无限库存 ∞ 的商品永远不参与补货**（想「限量但不补货」就把它设成 ∞）。
* **每个补货日只补一次**（存档记基准日），服务器在补货时刻之后重启**不会重复补**；刚打开开关时也只记基准日、不立刻全场补满。
* 补货后给全服发一条绿字提示；购物城底栏会显示「**每日补货 00:00（现实时间）**」，售罄时玩家知道只是暂时没货。
* 配置项在 `[mall]` 段：`mallRestockEnabled` / `mallRestockMode` / `mallRestockTime` / `mallRestockAmount`（游戏内改了会写回配置文件）。

### 3. 侧栏：一屏 6 个 + 平滑滚动动画

* 左侧模块区**一屏固定显示 6 个**，第 7 个起鼠标放在左栏**滚轮**上下滑（**普通模式与编辑模式都能滚**）。
* 右侧一条 **2px 细滚动条** + 底部小字「滚轮查看其余 N 个模块」，一眼能看出下面还有几个。
* **滚动动画重做**：滚动位置从「整行跳」改成**像素级平滑位移**（帧率无关的指数逼近，30 FPS 和高刷屏手感一致），
  滚动过程中上下各有一行**滑进 / 滑出**（列表带裁剪，绝不会蹭到左下角玩家信息卡），停下时又严丝合缝地落在整行上；
  滚动条滑块也是连续移动的。
* 切页签（点击 / 数字键 1-9 / 进「商店设置」）时选中的模块会**自动滚进可视区**，且只在你切换选中项那一刻调整。
* **手感二次优化**：滚得多就滑得快（同样的到达时间，约 80~120ms 到位），连滚多格不会「追不上」；
  滚轮支持**小数累积**（触控板也能滚）；裁剪区严格对齐列表带，滚动时**不再露出上一行的半条边**。
* 顺手修掉：编辑模式「新模块位置」空槽会盖住第 6 个模块；拖拽换位时最近槽位算偏 30px（拖到哪儿都插偏一格）。

### 3.1 新增：模块重命名（编辑布局里右键页签）

* 管理员进「编辑布局」→ **右键**左侧模块页签 → 输入新名字（留空 = 恢复原名）。
* 侧栏与页面标题只显示**新名字**；「商店设置」里显示 **新名（原名）**，
  例如把「每日收购」改成「每日任务」→ 设置页里是 **每日任务（每日收购）**，一眼能对上号。
* **只改显示名，模块 id 不变**：存档、配置、动作包、服务端校验全按 `daily / buyback / …` 走，
  改名不影响任何功能，也不影响以后新增模块。
* 名字随侧栏布局一起存进存档（`SidebarLayout.names`），改名后**立刻静默同步**给所有在线玩家，不用重启。
* 自动清洗：去掉 `§` 格式符与控制字符、压缩连续空格、最长 **12 字**（超出自动截断并提示），非管理员无法改名；
  「重置布局」会把自定义名一起恢复默认。

### 3.2 新增：商店设置 → 摊位 → 下架时间

* 模块下拉里多了 **摊位**：这里没有「添加条目」（商品由玩家自己上架），只有 **下架时间** 设置。
* 三种模式：**永久**（默认，行为不变）/ **游戏时间（天）** / **现实时间（小时）**；填 0 也等于永久。
* 开启后会实时改：摊位页每件商品价格右侧显示 **剩 X 天 / 剩 X 时 / 剩 X 分 / 即将下架**。
* **到期不吞物品**：剩余库存全部退回（在线进背包、背包满或离线进邮箱），并给摊主一条黄字说明；
  老存档里没有上架时刻的商品会先补打时间戳，不会被"立刻下架"。

### 3.3 新模块：玩家求购（悬赏）

* 侧栏新增 **玩家求购** 页（市场分组）。**主手**拿「想要的物品」、**副手**放「愿意付出的物品」（可选），
  点「发起求购」填 **要几个 / 悬赏多少金币** 即可发布。
* **悬赏在发布时就托管**（金币从余额扣、副手整叠收走），所以交付的人**一定拿得到报酬**；
  别人点一条 → 「交付」→ 服务端清点背包、收走物品、当场付悬赏（金币装不下转金钱邮件，物品进背包或邮箱）。
* 发布者可以随时**撤销**，托管的悬赏原样退回；到「下架时间」也会自动撤下并退回。
* **商店设置 → 求购**：开关 / 每人条数 / 手续费 % / 单笔上限 / 下架时间（永久 · 游戏天数 · 现实小时），
  页面还能看到全部求购并**强制撤销**；全服保留条数超限时最老的自动退款，防止刷列表。

### 4. 出货箱修复（玩家反馈）

* **「出货箱吞东西、钱没到账」——已修**：结算时**先把物品扣掉、最后才入账**，而余额上限一到顶，入账只会加
  「装得下的部分」——于是余额满的玩家物品照扣、钱只到账一部分甚至 0。
  现在**把余额剩余空间也当成一种额度**：只卖真能付得出钱的那些，装不下的**原样留在箱子里**（下次继续），
  并给在线玩家一条黄字说明；另有兜底（极端情况差额转金额邮件），绝不静默销毁。
  *实测：64 个原木 / 单价 20 / 余额 95 / 上限 100 —— 修复前「物品 0、余额 100」（吞 64 件只给 5 星币），
  修复后「一件不卖、64 件都在」；单价 2 时只卖 2 件（+4 星币）、箱子剩 62 件，分毫不差。*
* **「放进去、重进出货箱界面物品就没了」——已修**：出货箱容器的 `setChanged()` 是「把整个容器写回存档」，
  而 vanilla `SimpleContainer.setItem()` 内部**会回调 `setChanged()`** —— 构造函数里逐格填内容时，
  第 0 格刚填完就把「其余还是空」的容器写回存档，**第 1 格之后的物品当场被清空**
  （实测复刻：打开一次界面后存档只剩第 0 格）。现在装载期间用 `suppressWriteBack` 挡住回写：
  **装载只读、改格才回写**，箱内容与打开前完全一致。
* **结算时正开着出货箱界面会把卖掉的物品「变回来」（刷物）——已修**：结算后按存档刷新一下打开着的界面。
* **改小 `shippingLevelSlots` 会连物品一起删——已修**：缩容时先合并进前面的空格，放不下就原样保留，绝不销毁
  （实测 27 格各 1 件 → 配置改成 9 格，物品仍是 27 件）。
* **「加了橡木条目，别的木头也一起收」——规则优先级已修**：规则匹配原来是「第一条命中的赢」，
  而新加的条目是**追加在末尾**的，默认规则里又有 `#minecraft:logs=3`（所有原木按 3 收），
  于是新加的 `minecraft:oak_log=6` **根本不生效**。现在改成「**越具体越优先**」：
  物品 &gt; 整模组 &gt; 标签，同级里写在前面的优先。
  *实测 `["#minecraft:logs=3", "minecraft:oak_log=6"]`：10 个橡木按 6、10 个云杉按 3，合计 90 星币。*
  > 顺带说明：默认规则里那行 `#minecraft:logs=3` **本来就会把所有原木算进可收清单**——
  > 不想收其它木头，把这一行删掉（管理页右键删除）即可。

### 5. 界面与其它

* **编辑布局界面删掉两行说明文字**（工具条卡片里那行“按住页签拖动换位…”与模块管理标题下那行），

* 输入弹窗新增**选项字段**（一排按钮 + 「当前：X」，和品质按钮同一套观感），以后开关类设置不用再手打数字。

  现在点开下拉时，被面板盖住的那几行**不再画物品图标**，面板宽度也改成与清单同宽，看上去就是一张正经菜单；

### 5. 升级说明

* **服务端**：把 `server_shop_mod-1.15.0.jar` 放进 `mods/`，**并删掉旧的 `server_shop_mod-1.14.0.jar`**（同一 modId 不能同时存在两个 jar）。

## Part 2 · English Changelog

### 1. Fixed: players were kicked when the shop data got too big (important)

* **Symptom**: opening the shop disconnected the player; the client wrote a `disconnect-…-client.txt` containing
  `Failed to decode packet 'clientbound/minecraft:custom_payload'` and
  `Tried to read NBT tag that was too big; tried to allocate: 2097118 + 36 bytes where max allowed: 2097152`.
* **Cause**: vanilla refuses any single NBT **larger than 2 MiB**. After a whole-mod Mall import (up to 2000 items) the shop
  snapshot crossed that line, so **every player opening the shop got kicked**; the client→server "import mod" packet used the
  same `readNbt` path and could crash the same way.
* **Fix**: sync data is now **gzipped and split into 512 KiB chunks**, reassembled and inflated on the other side with a custom
  64 MiB limit — the vanilla 2 MiB cap is no longer involved in either direction. It is also **cheaper on bandwidth**
  (shop data is full of repeated item ids).
* **Resilient**: a timed-out, oversized or corrupt chunk group is **logged and dropped** — that one action simply does not
  apply; it never turns into a "Network Protocol Error" disconnect again.
* **Leaner snapshot**: admin-only lists (shop / buyback / Mall management lists) are now sent to admins only.

### 2. New: scheduled restock for the Mall

* Where: **Shop Settings → module *Mall* → “Restock”**.
* Four fields (toggles are buttons, no typing):
  * **Scheduled restock: off / on**;
  * **Time basis: real time / game time** (real = same boundary rule as the daily quota reset; game = same as the shipping
    bin settlement, 06:00 = game tick 0);
  * **Restock time** (`HH:mm`, digits are auto-colonised `0600` → `06:00`; a bad value is shown in red and refused);
  * **Restock amount**: `0` = each item refills to **its own amount**; `>0` = **every item** refills to that number.
* Each item remembers its **restock target** (the stock you entered when listing/editing/importing), and refills back to it.
  **Unlimited (∞) items never take part** — set an item to ∞ if you want "limited but not restocked".
* **Once per restock day** (the day is stored in the save), so restarting the server after the restock time does **not**
  refill twice; switching the feature on only records the baseline day instead of instantly refilling everything.
* A green server-wide message is sent on restock, and the Mall footer shows “**Restock daily at 00:00 (real time)**” so players
  know a sold-out item is only temporary.
* Config keys live in `[mall]`: `mallRestockEnabled` / `mallRestockMode` / `mallRestockTime` / `mallRestockAmount`
  (changing them in game writes the config file back).

### 3. Sidebar: 6 rows on screen + smooth scrolling

* The left module column now shows **exactly 6 rows**; from the 7th on, hover the column and **use the wheel**
  (works in normal mode *and* in layout-edit mode).
* A **2px scrollbar** on the right plus a small “Scroll for N more” line make the overflow obvious.
* **Scrolling was reworked**: it no longer jumps a whole row at a time — the position is now **interpolated in pixels**
  (frame-rate independent exponential approach, identical feel at 30 FPS and on high-refresh displays). A row slides in and
  out at the edges (the list band is clipped, so it never bleeds onto the player card), and it always settles exactly on a row.
  The scrollbar thumb moves continuously too.
* Switching tabs (click / number keys 1-9 / entering Shop Settings) scrolls the selected module into view, and only when the
  selection actually changes.
* Also fixed: the “new module” empty slot in edit mode used to cover the 6th module; drag-reorder picked a slot 30px off
  (it always inserted one row away from where you dropped it).
* **Second pass on the feel**: the further it has to travel, the faster it slides (same ~80–120 ms arrival — multi-notch spins
  no longer trail behind); the wheel now **accumulates fractional deltas** so trackpads work too; and the clip band is aligned
  exactly to the list so a **sliver of the outgoing row no longer peeks out** while scrolling.

### 3.1 New: rename a module (right-click a tab in layout-edit mode)

* Admins open “Edit layout” and **right-click** any module tab, then type the new name (leave empty to restore the original).
* The sidebar and page titles show **only the new name**; “Shop Settings” shows **new name (original)** — renaming “Daily Buyback”
  to “Daily Quests” shows **Daily Quests (Daily Buyback)** there, so you can always tell which module it is.
* **Display name only — the module id never changes**: saves, configs, action payloads and server validation all keep using
  `daily / buyback / …`, so renaming cannot break anything and future modules keep working.
* Names are stored next to the sidebar order (`SidebarLayout.names`) and **silently re-synced to every online player**
  immediately — no restart needed.
* Input is sanitised: `§` format codes and control characters stripped, whitespace collapsed, capped at **12 characters**
  (auto-truncated with a chat notice); non-admins cannot rename; “Reset layout” also restores the default names.

### 3.2 New: Shop Settings → Player stalls → Expiry

* The module dropdown now has **Player stalls**: no “add entry” there (players list their own items), just the **expiry** setting.
* Three modes: **permanent** (default, behaviour unchanged) / **game time (days)** / **real time (hours)**; an amount of 0 also
  means permanent.
* Takes effect immediately: on the stall page each listing shows **Xd left / Xh left / Xm left / expiring** next to its price.
* **No items are ever eaten**: remaining stock is fully returned (inventory while online, mailbox if the inventory is full or
  the owner is offline) plus a yellow notice; listings from old saves get their timestamp stamped first instead of expiring at once.

### 3.3 New module: player requests (bounties)

* New **Requests** page in the sidebar (market group). Hold the item you **want** in your main hand and the item you are
  **willing to pay with** in your off hand (optional), then click “Post request” and fill in **how many** and **how many coins**.
* **The reward is escrowed when you post it** (coins deducted, off-hand stack taken), so whoever delivers **always gets paid**.
  Others click a row → “Deliver”: the server counts the items in their inventory, takes them, and pays the reward immediately
  (coin overflow goes to a money mail, items go to the inventory or mailbox).
* Posters can cancel any time and get the escrow back; the expiry setting also auto-cancels and refunds.
* **Shop Settings → Requests**: on/off, per-player limit, fee %, max reward, expiry (permanent · game days · real hours),
  plus a list of all requests with **force-cancel**; when the global cap is exceeded the oldest one is refunded automatically.

### 4. Shipping bin fixes (player reports)

* **“The bin ate my items and the money never arrived” — fixed.** Settlement **removed the items first and credited the
  money afterwards**, but `credit()` only adds what the balance cap still allows — so a player at the cap lost the items
  while receiving part of the money, or none at all. The remaining **balance room is now treated as a budget** (together
  with the daily quota): only what can actually be paid for is sold, the rest **stays in the bin** for the next day, and the
  online player gets a yellow note. A money-mail fallback covers the extreme case, so value is never destroyed.
  *Measured: 64 logs at 20 each, balance 95 / cap 100 — before: “items 0, balance 100” (64 items eaten for 5 coins);
  after: nothing sold, all 64 items kept; at price 2 exactly 2 items sell (+4 coins) and 62 remain.*
* **“Items vanish as soon as you reopen the bin” — fixed.** The bin container’s `setChanged()` writes the *whole*
  container back into the save, and vanilla `SimpleContainer.setItem()` **calls `setChanged()` internally** — so filling
  the container cell by cell in its constructor wrote the *still-empty* container back after the very first cell, wiping
  every slot from index 1 on (measured with a faithful replica of the vanilla contract: after one open, only slot 0
  survived). Loading is now guarded by `suppressWriteBack`: **loading is read-only, only real edits write back**.
* **Settlement while the bin screen was open could “resurrect” sold items (dupe) — fixed**: the open container is now
  refreshed from the save after settlement.
* **Shrinking `shippingLevelSlots` used to delete items — fixed**: shrinking now merges items into free slots and keeps
  whatever does not fit (measured: 27 slots × 1 item → config reduced to 9 slots → still 27 items).
* **“I added an oak entry but other woods are still accepted” — rule precedence fixed.** Matching used to be
  “first match wins”, while entries added from the admin screen are **appended at the end**; the default rules already
  contain `#minecraft:logs=3` (every log at 3), so a new `minecraft:oak_log=6` **never took effect**. Matching is now
  **most-specific-first**: item &gt; namespace &gt; tag, ties by list order.
  *Measured with `["#minecraft:logs=3", "minecraft:oak_log=6"]`: 10 oak settle at 6 and 10 spruce at 3 — 90 coins.*
  > Note: the default `#minecraft:logs=3` line **by itself** already accepts every log type — delete that line (right-click
  > it in the admin screen) if you only want specific woods.

### 5. UI and other changes

* **Removed two help lines from the layout editor** (the “drag a tab to swap…” line inside the toolbar card and the
  “click Add or drag…” line under the module manager title); the buttons moved to the middle of the card and the module
  manager now fits **7 rows instead of 6**.
* **Shipping bin “Daily quota” gained two time fields**: **settlement time (game time)** and **quota reset (real time)**,
  both `HH:mm` inputs with auto-colon and double validation (red hint client-side, refused server-side).
* Input dialogs gained a generic **choice field** (a row of buttons plus “now: X”), so toggle-style settings no longer ask
  you to type numbers.
* **The shipping bin’s Sort / Category dropdown is no longer covered by the list**: item icons are rendered as 3D items
  (z = 150, and they write depth), so a flat panel drawn later cannot cover them. Rows behind an open panel now **skip their
  item icon**, and the panel is as wide as the list, so it reads as a proper menu. The hover tooltip is now drawn after the
  panel instead of before it.

### 5. Upgrade notes

* **Server**: drop `server_shop_mod-1.15.0.jar` into `mods/` and **delete the old `server_shop_mod-1.14.0.jar`**
  (two jars with the same mod id cannot coexist).
* **Client**: must install the **same 1.15.0 jar**. The payload channel version is now 2: if only one side is updated you get a
  readable “channel version mismatch” on join (an old client facing the new format would otherwise crash with a protocol error).
* **Config**: nothing to do by hand. The new `[mall]` section is written with defaults; restock is **off** until you enable it.
* **Saves**: new fields (Mall restock target `stockMax`, restock baseline day) default cleanly for old saves; existing items
  initialise their restock target from their current stock, so nothing ends up with “target 0, never restocked”.
* **Checksum**: the jar SHA-256 is in `SHA256校验.txt` inside the release package.
